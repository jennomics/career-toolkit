# Session Retro — 2026-07-30

## What shipped
1. **Candidate Profile feature** — structured, multi-section profile with 6 new models (CandidateProfile, CareerRole, SignatureStory, ProfileMetric, UnresolvedItem, WritingSample), full API routes, UI page at /profile, seed script with all real data
2. **Intelligence layer wiring** — profile context injected into all 3 resume/cover letter generation endpoints via shared utility (src/lib/profile-context.ts)
3. **Generation-ready gate** — blocks resume gen until all 8 unresolved items are resolved

## What went well
- Once the real state of main was understood, implementation was clean and fast
- Groundcrew command execution worked perfectly for remote setup (create .env, merge, generate, db push, seed)
- Profile-context utility design is clean — additive injection, graceful degradation, selective story matching
- Sub-agent delegation for the full feature build saved significant time

## What caused friction
1. **Stale shallow clone** — started with a shallow clone of feat/job-library missing full history, hid the fact that v0.4.0 groundcrew existed and main was far more evolved
2. **Branch divergence** — feat/job-library and main had completely diverged. Built feature on wrong base first, had to redo on main
3. **Missing .env** — lost during branch switching, caused cascading failures. Recurring systemic problem
4. **Wasted port-detection commit** — pushed code to groundcrew that conflicted with v0.4.0 architecture already deployed
5. **Too many manual steps relayed to user** — should have used groundcrew commands earlier

## Key insights
- At session start, immediately verify local state via groundcrew command: `git branch && git log --oneline -3 && ls .env`
- Never build on feat/job-library — it's dead. Always branch from main
- .env is the most fragile piece — not in git, lost on branch switches, everything fails without it
- Groundcrew v0.4.0 does NOT run prisma db push or seed scripts automatically — send those as explicit commands
- Full-depth clone (or at minimum checking all branches) prevents architecture confusion

## Time estimate
- ~60% of session was infrastructure/branch confusion
- ~40% was actual feature development
- With the startup checklist, this should flip to 80%+ productive next time
