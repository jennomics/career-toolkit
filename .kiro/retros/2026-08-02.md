## What caused the most friction
1. **Branch divergence** — feat/job-library vs main caused 30+ minutes of confusion and multiple failed merges
2. **Sub-agent generated fake data under real identity** — the seed script had fabricated career details attributed to Jenna. Critical data provenance failure.
3. **Neon branching copies data** — assumed a new "database" would be empty. Had to manually purge 134 real jobs from the demo DB.
4. **filter-repo cascade** — removed remote, broke npm link, caused merge conflicts, GitHub 404'd temporarily
5. **Prisma generate forgotten after .next deletion** — led to "Internal Server Error" that looked like an auth issue
6. **Tunnel instability** — EADDRINUSE from orphaned processes, URL changes on every restart, 502/1033 errors throughout

## Process improvements captured
- Never use real person's data in seed scripts, even temporarily
- After `rm -rf .next`: always run `prisma generate` before `npm run dev`
- Neon branches aren't empty — purge or use a new project for demo
- After filter-repo: re-add remote, force push, expect breakage everywhere
- The private/public deployment split should have been designed first, not retrofitted
