# One Filled Thing style guide applied to Career Toolkit

A comprehensive visual restyling across 54 TSX files replaces the default Tailwind gray/blue/purple card-based UI with the "One Filled Thing" design system: paper backgrounds, ruled rows instead of cards, ink/live-only color palette, Zen Kaku Gothic New + DM Mono typography, 720px single column, and 0-radius/0-shadow tokens. The foundation is `globals.css` with Tailwind v4 `@theme` tokens that neutralize all radius and shadow utilities at the theme level, plus Google Font setup in `layout.tsx`. The conversion is consistent across all 21 page layouts and 30+ shared components.

Watch for: residual `border-purple-600` spinners and `text-yellow-600` in resume/page.tsx (confirmed), a broken empty `hover:` class in claims/page.tsx (confirmed), `disabled:bg-gray-400` leaking a non-token fill in ResumeTab.tsx (confirmed).

**Verdict**: NEEDS_CHANGES

## High-level view

The token layer in globals.css provides a safety net: every `--radius-*` is 0, every `--shadow-*` is none, so residual `rounded` or `shadow-sm` utility classes in components that weren't fully cleaned are visually neutralized. The `prefers-reduced-motion` media query correctly zeros out all durations.

The card-to-rules conversion is thorough: `border-t border-rule` replaces card wrappers across all pages, stats use `font-mono`, labels use `text-meta font-mono uppercase tracking-widest`, and buttons follow the 3-tier system (live outline primary, ink outline secondary, underline tertiary) with 48px height.

A handful of stray non-token colors leaked through in `src/app/resume/page.tsx` (two `border-purple-600` spinners, one `text-yellow-600` conditional) and one `disabled:bg-gray-400` in `src/app/company/[slug]/ResumeTab.tsx`. These produce visible off-palette color on screen and need fixing before the style guide can be considered fully applied.

## Residual off-palette colors in resume workflow

The resume builder page (`src/app/resume/page.tsx`) has two spinner elements that retained `border-purple-600`:

```tsx
// ~line 689
<div className="inline-block w-6 h-6 border-2 border-purple-600 border-t-transparent animate-spin" />

// ~line 843
<div className="inline-block w-6 h-6 border-2 border-purple-600 border-t-transparent animate-spin" />
```

The same page has a conditional that introduces `text-yellow-600`:

```tsx
<span className={`text-xl font-bold ${
  gapResult.coverage >= 70 ? "text-ink-72" : gapResult.coverage >= 40 ? "text-yellow-600" : "text-ink-72"
}`}>
```

The company slug ResumeTab correctly converts its spinner to `border-ink`, showing the intent was there but not carried through to resume/page.tsx. The yellow conditional uses color to categorize (coverage quality), which the style guide explicitly forbids.

## Broken hover class in claims inline edit

In `src/app/claims/page.tsx` line 189:

```tsx
className="text-left w-full hover: rounded px-1 -mx-1"
```

The `hover:` prefix is dangling with no utility after it. Left behind when `hover:bg-blue-50` was stripped.

## animate-spin and the motion contract

The style guide states "nothing loops, pulses, bounces" and caps all motion at 260ms. `animate-spin` is an infinite loop. The `prefers-reduced-motion` block in globals.css forces `animation-duration: 0ms !important`, so users with that preference see no animation. For everyone else, the spinner loops indefinitely. There's no non-looping CSS-only alternative that communicates "loading" effectively, so this may be an acceptable exception, but it should be a deliberate decision.

## `font-semibold` mapped to unavailable weight

Eighteen added lines use `font-semibold` (weight 600) where the font only loads 300 and 500. The browser falls back to 500, so the visual result is correct, but `font-medium` would match the loaded weight explicitly. Non-blocking, but worth a cleanup pass.
