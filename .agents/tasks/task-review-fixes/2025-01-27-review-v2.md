# Security hardening, analytics corrections, and data exposure fixes (v2)

All three issues from the v1 review have been addressed: skills `deleteMany` is now inside the `$transaction` array when both skills and status change; the fallback conversion path has a detailed comment documenting the known approximation; and the integrity route warning now correctly says "will reject all requests in production". Build, lint, and 341 tests pass.

Watch for: demo-mode GC block in middleware step 4 is now unreachable dead code (confirmed, non-blocking); the `$transaction` result indexing (`results[1]` vs `results[0]`) is fragile if the ops array shape changes in future (confirmed, non-blocking).

**Verdict**: APPROVED

## High-level view

The transaction fix builds the `ops` array conditionally and executes atomically. The return-value indexing (`skills !== undefined ? results[1] : results[0]`) couples result extraction to the array construction order — correct today, fragile under future edits.

The middleware now handles all `/api/gc/` paths at step 3b (returning either 401 or `next()`), which means the demo-mode GC block at step 4 is unreachable dead code. Remove it to avoid confusion about where GC access control lives.

## Dead demo-mode GC block in middleware

Step 3b (`isGCRoute`) always returns for any path starting with `/api/gc/` — either a 401 rejection or `NextResponse.next()`. Execution never reaches step 4's `if (pathname.startsWith("/api/gc/"))` block. In the pre-fix middleware, GC routes fell through to step 4 where demo mode could block them. Now that step 3b intercepts first, the demo-mode check is dead code. A future reader looking at the demo-mode section will incorrectly assume that's where GC blocking happens.

## Transaction result indexing

```typescript
const ops = [
  ...(skills !== undefined
    ? [prisma.jobSkill.deleteMany({ where: { jobId: id } })]
    : []),
  prisma.job.update({ ... }),
  prisma.applicationEvent.create({ ... }),
];
const results = await prisma.$transaction(ops);
const updatedJob = skills !== undefined ? results[1] : results[0];
```

The index calculation is a positional coupling. An interactive transaction (`prisma.$transaction(async (tx) => { ... })`) would let each operation's result be named directly, eliminating the index math.
